# Alpha — Architectural and Mathematical Specification

## 1. Introduction
Project `Alpha` formalizes lambda calculus syntax equipped with explicit action functions, shift operators, well-founded recursion measures, and inductive alpha-equivalence.

Historically created in 2018 (`00.v` by Georgy Dunaev), the project explores:
- Inductive term construction: `atom`, `appl`, `lamb`, `shft`.
- Action functions: `varp` (variable transposition / replacement) and `subs` (scope-protecting abstraction).
- Non-structural recursive action (`act`) proven terminating via custom well-founded metric `lenf(f) + lent(t)`.
- Alpha-equivalence (`alp`) defined as an inductive equivalence relation with renaming axiom `axi`.

---

## 2. Formal Grammar

### Terms (`term`)
```
t ::= atom(v)
    | appl(M, N)
    | lamb(x, M)
    | shft(M)
```
- `atom(v)`: Atomic variable node for variable `v`.
- `appl(M, N)`: Function application node applying `M` to `N`.
- `lamb(x, M)`: Binder node binding variable `x` in body `M`.
- `shft(M)`: Explicit scope shift lifting free variables by one binder level.

### Functions (`func`)
```
f ::= varp(y, x)
    | subs(F, x)
```
- `varp(y, x)`: Variable action replacing target variable `x` with `y`.
- `subs(F, x)`: Extension operator shielding bound variable `x` from modification by sub-action `F`.

---

## 3. Well-Founded Termination Metric

Standard structural induction `{struct t}` fails for `act(f, t)` because when `t = atom(v)` and `f = subs(F, x)`, the recursive step evaluates `act(F, v)` where `atom(v)` is not structurally smaller than `t`.

To overcome this, a custom natural measure is defined:
```
lent(atom x)       = 0
lent(appl M N)     = max(lent M, lent N) + 1
lent(lamb x M)     = lent(M) + 2
lent(shft M)       = lent(M) + 1

lenf(varp y x)     = 0
lenf(subs F x)     = lenf(F) + 1

measure(f, t)      = lenf(f) + lent(t)
```

### Obligation Invariants:
1. **Atom Case (`subs F x` on `atom v`)**:
   `lenf(F) + lent(atom v) = lenf(F) + 0 < (lenf(F) + 1) + 0 = lenf(subs F x) + lent(atom v)`.
2. **Application Case Left**:
   `lenf(f) + lent(M) < lenf(f) + max(lent M, lent N) + 1 = lenf(f) + lent(appl M N)`.
3. **Application Case Right**:
   `lenf(f) + lent(N) < lenf(f) + max(lent M, lent N) + 1 = lenf(f) + lent(appl M N)`.
4. **Lambda Case (`subs f x` on `M`)**:
   `lenf(subs f x) + lent(M) = lenf(f) + 1 + lent(M) < lenf(f) + lent(M) + 2 = lenf(f) + lent(lamb x M)`.
   Notice the `+ 2` in `lent(lamb x M)` ensures that incrementing `lenf` by `+ 1` still strictly decreases the total measure by at least 1.
5. **Shift Case (`subs F x` on `shft M`)**:
   `lenf(F) + lent(M) < lenf(subs F x) + lent(shft M) = lenf(F) + 1 + lent(M) + 1`.

All obligations are linear integer inequalities decidable via Presburger arithmetic (`lia`).

## 4. Inductive Alpha-Equivalence (`alp`)

The relation `alp : term -> term -> Prop` is generated by:
- `ref`: Reflexivity `forall M, alp M M`.
- `sym`: Symmetry `forall M1 M2, alp M1 M2 -> alp M2 M1`.
- `tra`: Transitivity `forall M1 M2 M3, alp M1 M2 -> alp M2 M3 -> alp M1 M3`.
- `shf`: Shift Congruence `forall M1 M2, alp M1 M2 -> alp (shft M1) (shft M2)`.
- `app`: Application Congruence `forall M1 M2 N1 N2, alp M1 M2 -> alp N1 N2 -> alp (appl M1 N1) (appl M2 N2)`.
- `lam`: Lambda Congruence `forall M1 M2 x, alp M1 M2 -> alp (lamb x M1) (lamb x M2)`.
- `axi`: Renaming Axiom `forall M y x, alp (lamb x M) (lamb y (act (varp y x) M))`.

## 5. Python Logic Engine (`alpha_engine`)

To provide immediate, executable verification without requiring Coq toolchains:
- `alpha_engine.terms`: Data classes for terms, actions, measures, capture-avoiding action reduction, canonical de Bruijn normalization, and alpha-equivalence testing.
- `alpha_engine.terms.TermGraph`: Direct syntax graph and binding arc builder for graph-isomorphic equivalence checking.
- `alpha_engine.syntax_verifier.CoqVerifier`: Static AST and syntax balance checker for `.v` scripts.
